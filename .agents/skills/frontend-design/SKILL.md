# Build a frontend

Implement the requested interface with working behavior and a coherent visual language. Start from the user's references, the existing product, and local design documents. A small change should fit the product; it does not need a new aesthetic direction.

For a new surface, infer the audience, purpose, and appropriate information density. Make routine visual choices and proceed. Ask only if a missing brand or product decision would materially change the result.

- Use the existing component library, tokens, typography, and layout conventions where they fit.
- Make hierarchy, spacing, copy, and interaction states clear. Use cards, decoration, color, and motion when they serve the product.
- Preserve brand boundaries: another project's palette or signature motif is not a universal template.
- Prefer familiar, readable controls and fonts for utility interfaces. Distinctive typography or imagery should fit the requested style.
- Keep keyboard access, focus, responsive layouts, and reduced-motion behavior intact.
- Match implementation complexity to the task. Reuse a motion library already present rather than adding one for a trivial effect.

Verify the affected flow and rendered states when visual behavior matters. Report the result and any material limitations concisely. Do not add a compulsory design document, a universal font ban, or a model-specific pep talk.
